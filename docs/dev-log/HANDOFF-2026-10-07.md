## 1. 这是什么项目

**CodeLab / LabCode** —— 面向单片机（ESP32 为主、STM32 为辅）的桌面 IDE，把「写码 → 编译 → 烧录 → 串口」这条硬链路做厚。

- **主赛道**：硬件编程 + 烧录（命脉，一切取舍以这条链路是否顺为准）
- **技术栈**：Electron 44 + React 19 + TypeScript 5.9 + electron-vite 5 + Vite 7；Monaco（编辑器）/ xterm + node-pty（终端）/ serialport（串口）
- **当前规模**：85 个 Agent 工具、25 个自检脚本（674 断言）、4 个静态扫描器
- **竞品**：对齐 TrieCode；竞品拆解在仓库外的 `D:/工作/代码实验室/codelab-doc/`
- **AI 亮点**：三通道网关（本地 llama / BYOK 自带 Key / 官方登录+积分），都支持 function calling

**🔴 研发红线（最重要的一条）**
> 「自己研发，不要引用其他人的」——能力可以对照别人，**代码必须自己写**。

## 2. ⚠️ 环境约束（先看这段，能省一小时）

这个沙箱环境和普通开发机不一样，**别在这上面浪费时间**。

### 工具一律用绝对路径
| 用途 | 路径 |
|---|---|
| node | `C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-3/node.exe` |
| git | `C:/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin/git.exe` |

系统 Git **不在 PATH**，只能用上面这个 PortableGit。

### Bash 工具的 shell 是坏的
- `ls` / `cat` / `tail` 等 coreutils **全部 command not found**；只有 Windows 内置命令和直接调 node/git 二进制能跑。
- **不要用 `npm run xxx`**：npm 是 bash shim，这个坏 shell 里跑不起来。直接 `node <路径>/<cli>.js`。
- 读文件用 Read 工具、找文件用 Grep 工具，别用 shell 的 cat/ls/grep。
- **`git add` 多文件必须写成单行空格分隔**，用 `\` 续行会被坏 shell 吞掉参数、触发 `sandbox-center cmd decisionRecord missing actual resource subject`。复合命令（多条 `&&`）偶发同样报错 → **拆成单条**跑。

### 构建
`out/` 与 `out-b*/` 都在 .gitignore，构建产物不会污染 git status。默认构建直接落到 `out/` 即可：
```bash
node "D:/工作/代码实验室/codelab-desktop/node_modules/electron-vite/bin/electron-vite.js" build
```
（若命中删除护栏就失败，则改指向全新递增目录 `out-b01`、`out-b02`…，用完清掉。）

### 两条「沙箱做不到」的事（别反复试）
1. **Electron 起不来**（GPU 子进程崩溃）→ 整棵渲染层 UI **只能真机验**。`file://` 下 module script 会静默不执行（探针恒 0 且零报错，**极易误判成"没 bug"**）；CDP 在本机 Chrome 上连 about:blank 都超时。
2. **打包进程 spawn 不动 arduino-cli** → 烧录端到端**只能用户真机插板验证**。对照实验：Bash 直跑同一个 exe 完全正常（core list / compile 都成功），所以是沙箱限制，**不是产物缺陷**。

- 工具链位置：`%APPDATA%/codelab-desktop/tools/`（`arduino-cli.exe`、`openocd-esp32 v0.12.0-esp32-20260831`、`llvm/clangd`）

## 5. ★ 本轮重点：层2 深度编译预检（commit 390e46d，已完成）

**解决的问题**：层1 保存即预检是**纯静态**（板卡合法性 + 引脚冲突，零 spawn，1 秒内出结论）；但依赖缺失、语法错、库找不到这类问题要等真编译才知道。层2 = 停输 2.5s / 保存 / 换板换项目时，用 arduino-cli **真实编译**一次，提前暴露这些问题。

### 设计决定（与层1/手动编译完全解耦）
- **独立 IPC**（`sketch:deepCompilePrecheck`）+ **独立状态**（`deepCheck`）+ **独立圆点**（violet 色，与层1 语义分开）。不发射 task 事件、**不触碰 `compileState`/`buildStage`/`buildError`**——避免与手动编译状态打架。
- **默认关闭**（实验性）：真实编译几十秒，不能每次击键都跑。设置面板开关，localStorage `codelab-deep-precheck` 持久。
- **护栏**：未开项目 / 未选板 / `busy` / 工具链不可用 一律不跑。
- 复用 `compileSketch`（子进程调官方 arduino-cli），180s 超时 kill，结果只回传输出**尾部 4000 字**（错误通常在末尾，避免撑爆 IPC）。

### 顺手修的两处自身隐患
1. **缓存键由 `content.length` 改为 FNV-1a 内容指纹**：等长改写（改一个字符）会让缓存误命中，把上次「通过」当本次结论——**误导性通过，假成功比报错更骗人**。
2. **关掉开关时清挂起防抖定时器 + 递增 seq 作废在飞结果**：否则 2.5s 内关掉，挂起定时器仍触发旧闭包跑完编译、30s 后圆点自己亮回来（关了还亮）。

### 验证
tsc 双过 exit 0；`scan-ipc-handlers` 201→201 / 0 遗留；`electron-vite build` 通过；main/preload/renderer 三产物 grep 均含 `deepCompilePrecheck`。

## 7. 🔴 铁律（改代码前必读，都是踩过坑换来的）

1. **唯一颜色源 = `src/renderer/src/assets/theme.css`**。渲染层（main.css + 所有 .tsx 内联 style）**不准出现 hex/rgb/rgba 字面量**，一律 `var(--token)`。状态色只一套：绿 `--success` / 黄橙 `--warning` / 红 `--danger` / 蓝 `--accent` / 紫 `--violet`。
   *坑*：SVG 的**表现属性**（`stroke=` `fill=` **`stop-color`** **`flood-color`**）**不认 `var()`**，必须写进 `style={{ fill: 'var(--x)' }}`。
2. **误报比漏报更烦人**。引脚检测/编译诊断/缓存这类判定，宁可漏报也不要给用户压根没写的东西——用户照着警告去改、改完警告还在，等于毁掉这个功能的可信度。同理**「误导性通过」和「漏报」一样有害**（层2 缓存键踩过这个坑）。
3. **注释必须先剥再扫源码**。`stripComments()` 处理行尾 `//`、块注释、跨行块注释，且带字符串/转义识别。**pinConflict 与 wiringService 都先剥再扫**。剥完还要留**反向断言**：`code(); // 注释` 里的真代码必须照报。
4. **同一块信息只能有一个取值来源 / 一个可编辑来源**。板卡/端口/框架只在「硬件目标」面板可改。同一个坑只修一半等于没修（SettingsModal 曾出现下拉显示 A、实际下载 B）。
5. **跑之前就 abort 的分支必须显式 `setCompileState('error')` + 清耗时/错误**。只写日志就 return，会让上一次的 success 卡 + Flash/RAM 用量残留（**假成功比报错更骗人**）。
6. **兜底定时器要跟着取消一起清**。编译 180s / 烧录 120s 的 `setTimeout` 必须在 cancel 里 `clearTimeout`，否则用户点「取消」后凭空多一条假错误。同理防抖定时器要在功能关闭时清理（层2 踩过）。
7. **流式日志铁律**（只增不减的日志）：ref 作唯一事实源、state 只是展示副本；有长度上限（App.tsx 现 20 万字符）；**对应面板没挂载时完全不 setState**；挂载时 120ms 节流。
8. **`setTabs`/`setX` 的 updater 必须纯**，不能在里面调另一个 setState（StrictMode 双调用会出错）。用「先算再提交」。
9. **改 `asarUnpack` 是 additive 操作**，永远不要拿新模式替换旧列表（曾把 node-pty/serialport 塞回 asar 导致串口+终端全废）。
10. **`spawnSync` 在主进程会卡住渲染层 IPC**。任何「输入即查」的下拉（如板卡搜索），后面是 `spawnSync` 的一律要防抖。
11. **先写测试再修代码**。测试能区分「是代码错还是我错」——多轮经验里失败的测试里有相当一部分是**测例自己写错**。别一红就动手改代码。
12. **静态扫描器必须造样例反向自测**。四件套初版分别产出过 267 / 130 / 22 条**假阳性**。口径宁漏勿误报，命中后人工核实。
13. **函数内引用其后定义的 `const`/ref 会 TDZ**（TS2448/2454）。`onChange` 早于 `schedulePrecheck` 定义这类，用 `xxxRef`（useRef 持有最新实现）破除——`schedulePrecheckRef`/`runPrecheckRef`/`scheduleDeepCheckRef` 都是这个套路。
14. **能力声明要诚实**。工具调用数、板卡数、断言数、通道数**以代码/脚本实际输出为准**，别信旧文档数字。做不了的事（如不做 GDB 就明说）绝不硬凑。

## 8. 🚧 死胡同（别重走）

- `file://` 下渲染层 module script **静默不执行**（探针恒 0 且零报错）→ 整树启动验不了。`check-render-boot.mjs` 沙箱超时是环境问题非回归。
- CDP（`Runtime.evaluate`）在本机 Chrome 上**连 about:blank 都超时**，不稳定；本机无系统 Chrome 可靠 headless 路径。
- 沙箱里打包产物 **spawn 不动 arduino-cli**（Bash 直跑正常）→ 烧录端到端只能真机。
- `check-ui-assets.mjs` 需传安装包目录参数——**用法问题，不是回归**。
- **JS 正则不支持 `\A`**：`\ATP` 被当字面量 `ATP` 匹配（`logExplainer` 曾因此误报）。
- **写二进制夹具别用 JS 字符串 `\xff`**：那是 U+00FF（UTF-8 占 2 字节），不是字节 0xff。用 `Buffer.from([0xff,...])`。分区表 label 真实是 `0x00` 收尾。
- **CMSIS-SVD 的 `derivedFrom` 是属性**（`<peripheral derivedFrom="GPIO">`），不是子元素。
- **`.ino` 必须显式 `-x c++`**：compile_commands 里的 `--driver-mode=g++` 对 clangd 无效，`.ino` 会解析失败（hover/definition 全 invalid）。对照实验坐实（`.cpp` 正常 / `.ino` 加 `-x c++` 正常 / `.ino` 只带 driver-mode 失败）。
- **clangd 首次解析 arduino-esp32 大头文件要十几秒**——慢 ≠ 坏，别当超时 bug。ESP32 `Serial.` 成员补全为空是 core 声明特性，演示成员补全用 `HardwareSerial mySerial(1); mySerial.`。
- **LSP 请求超时默认 30s 太短**：ESP32 重文件首补全会被掐断 → 编辑器侧透传放大到 60s，并转发 Monaco `triggerKind`/`triggerCharacter`（打字 `.` 时 triggerKind=2，clangd 才返回成员补全）。
- **ESP32-S3 / C3 / P4 原生 USB 共用 `303a:1001`**（硬件事实，物理分不开）→ 插 C3/P4 **不要**指望自动认准，得由用户/端口信息收窄。
- **`esp32-p4-function-ev` 是 PlatformIO-only + `svdChip:null`**（P4 无 arduino-cli 官方 core），属**合法收录**，别当成漏配去"修"。
- **工具调用按 index 累积，不是顺序单指针**：官方通道 SSE 与 llama 增量帧都可能在后续帧不带 id，用「单指针顺序配对」会把参数配错调用（`bb05ced` 修）。emitToolCalls 要幂等（`[DONE]` 与 end 都会触发）。
