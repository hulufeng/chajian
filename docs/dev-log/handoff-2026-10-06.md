## 1. 这是什么项目

**CodeLab / LabCode** —— 面向单片机（ESP32 为主、STM32 为辅）的桌面 IDE，把「写码 → 编译 → 烧录 → 串口」这条硬链路做厚。

- **主赛道**：硬件编程 + 烧录（这是命脉，一切取舍以这条链路是否顺为准）
- **技术栈**：Electron 44 + React 19 + TypeScript 5.9 + electron-vite 5 + Vite 7；Monaco（编辑器）/ xterm + node-pty（终端）/ serialport（串口）
- **竞品**：对齐 TrieCode；竞品拆解在仓库外的 `D:/工作/代码实验室/codelab-doc/`
- **AI 亮点**：三通道网关（本地 llama / BYOK 自带 Key / 官方登录+积分），都支持 function calling

## 2. ⚠️ 环境约束（先看这段，能省一小时）

这个沙箱环境和普通开发机不一样，**别在这上面浪费时间**。

### 工具一律用绝对路径
| 用途 | 路径 |
|---|---|
| node | `C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-3/node.exe` |
| git | `C:/Users/Administrator/.workbuddy/binaries/PortableGit/versions/1.2.0/mingw64/bin/git.exe` |

系统 Git **不在 PATH**，只能用上面这个 PortableGit。

### Bash 工具的 shell 是坏的
- `ls` / `cat` / `tail` 等 coreutils **全部 command not found**；只有 Windows 内置命令和直接调 node 二进制能跑。
- **不要用 `npm run xxx`**：npm 是 bash shim，这个坏 shell 里跑不起来。直接 `node <路径>/<cli>.js`。
- 读文件用 Read 工具、找文件用 Grep 工具，别用 shell 的 cat/ls/grep。
- 复合命令（`rm` + `git`、多条 `&&`）偶发报 `sandbox-center cmd decisionRecord missing actual resource subject` → **拆成单条**跑，必要时加 `dangerouslyDisableSandbox: true`。

### 构建要指向全新目录
```bash
node "D:/工作/代码实验室/codelab-desktop/node_modules/electron-vite/bin/electron-vite.js" build \
     --outDir "D:/工作/代码实验室/codelab-desktop/out-b01"
```
用**每次递增的新目录**（out-b01、out-b02…）：electron-vite/vite 会先清空 outDir，命中删除护栏就失败。用完 `rm -rf` 掉，别让它进 git status。

### 两条「沙箱做不到」的事（别反复试）
1. **Electron 起不来**（GPU 子进程崩溃）→ 整棵渲染层 UI **只能真机验**。`file://` 下 module script 会静默不执行（探针恒 0 且零报错，**极易误判成"没 bug"**）；CDP 在本机 Chrome 上连 about:blank 都超时。
2. **打包进程 spawn 不动 arduino-cli** → 烧录端到端**只能用户真机插板验证**。对照实验：Bash 直跑同一个 exe 完全正常（core list / compile 都成功），所以是沙箱限制，**不是产物缺陷**。

- 工具链位置：`%APPDATA%/codelab-desktop/tools/`（`arduino-cli.exe`、`openocd-esp32 v0.12.0-esp32-20260831`）

## 5. ★ 本轮重点：保存即预检（层1 已完成，commit 5f481b7）

**解决的问题**：以前引脚冲突、板卡无效这类问题要等点了编译才知道，中间还要来回切面板。现在保存/停输 1 秒后自动静态校验，结论直接晒在状态栏。

### 怎么用
- 状态栏右侧多一个圆点：`预检通过`(绿) / `引脚警告×N`(黄) / `引脚冲突×N`(红) / `未选有效板`(黄)
- **点击圆点** → 完整报告打进输出面板并展开

### 触发时机
1. 打开/切换项目（`projectRoot` 变）
2. 选/换开发板（`fqbn` 变）
3. 停输 1 秒防抖（编辑器 `onChange`）
4. Ctrl+S 保存后

护栏：未开项目 / 未选板 / `busy`（编译烧录进行中）都不跑。

### 涉及文件
| 文件 | 改动 |
|---|---|
| `src/main/index.ts` | `ipcMain.handle('sketch:precheck')`：板卡合法性 `boardRegistry.targetForFqbn` + 引脚冲突 `pinConflict.checkPinConflicts`，**纯分析零 spawn** |
| `src/preload/index.ts` | `window.api.sketch.precheck({projectRoot, fqbn, overlay})` + `PrecheckSnapshot` 类型 |
| `src/main/services/pinConflict.ts` | `checkPinConflicts` 加 `overlay` 参数（key=绝对路径，内部 `path.relative` 折算 rel，跑到项目外忽略） |
| `src/renderer/src/App.tsx` | `precheck` state + 触发逻辑；**与 `compileState` 完全解耦** |
| `src/renderer/src/components/StatusBar.tsx` | 可点击预检圆点（`dot()` 加可选 `onClick`） |
| `scripts/check-pin-conflict.mjs` | 新增 3 项 overlay 断言（22→25） |

### 两个关键设计决定（改动前先理解）
1. **`overlay` 覆盖层**：渲染层把**编辑器实时内容（未必落盘）**传进来，覆盖磁盘同名文件、补进未落盘新文件，其余磁盘文件照扫。
   *为什么*：否则「停输 1s 预检」看到的是上一份已保存快照，会给出**误导性的"通过"**。
2. **预检 state 与 `compileState` 解耦**：预检红点绝不污染编译成功卡。
   *为什么*：否则会出现「预检报冲突，但编译卡显示的是上一次的 success」这种自相矛盾（比报错更骗人）。

### 实现坑（下次改这里注意）
- `onChange`（靠前）引用了在其后定义的 `schedulePrecheck` → TS2448/2454「used before declaration」。
  解法：用 `schedulePrecheckRef`（useRef 持有最新实现）破除 TDZ，`saveTab` 也走 ref 以保持依赖数组稳定。同 `runPrecheckRef` 一个套路。

## 7. 🔴 铁律（改代码前必读，都是踩过坑换来的）

1. **唯一颜色源 = `src/renderer/src/assets/theme.css`**。渲染层（main.css + 所有 .tsx 内联 style）**不准出现 hex/rgb/rgba 字面量**，一律 `var(--token)`。状态色只一套：绿 `--success` / 黄橙 `--warning` / 红 `--danger` / 蓝 `--accent` / 紫 `--violet`。
   *坑*：SVG 的**表现属性**（`stroke=` `fill=` **`stop-color`** **`flood-color`**）**不认 `var()`**，必须写进 `style={{ fill: 'var(--x)' }}`。
2. **误报比漏报更烦人**。引脚检测/编译诊断这类判定，宁可漏报也不要报一条用户压根没写的东西——用户照着警告去改、改完警告还在，等于毁掉这个功能的可信度。
3. **注释必须先剥再扫源码**。`stripComments()` 处理行尾 `//`、块注释、跨行块注释，且带字符串/转义识别（`"a//b"` 里的 `//` 抹成空格而不是删）。**pinConflict 与 wiringService 都先剥再扫**。剥完还要留**反向断言**：`code(); // 注释` 里的真代码必须照报。
4. **同一块信息只能有一个取值来源 / 一个可编辑来源**。板卡/端口/框架只在「硬件目标」面板可改。同一个坑只修一半等于没修（SettingsModal 曾出现下拉显示 A、实际下载 B）。
5. **跑之前就 abort 的分支必须显式 `setCompileState('error')` + 清耗时/错误**。只写日志就 return，会让上一次的 success 卡 + Flash/RAM 用量残留（**假成功比报错更骗人**）。
6. **兜底定时器要跟着取消一起清**。编译 180s / 烧录 120s 的 `setTimeout` 必须在 cancel 里 `clearTimeout`，否则用户点「取消」后凭空多一条假错误。
7. **流式日志铁律**（只增不减的日志）：ref 作唯一事实源、state 只是展示副本；有长度上限（App.tsx 现 20 万字符）；**对应面板没挂载时完全不 setState**；挂载时 120ms 节流。
8. **`setTabs`/`setX` 的 updater 必须纯**，不能在里面调另一个 setState（StrictMode 双调用会出错）。用「先算再提交」。
9. **改 `asarUnpack` 是 additive 操作**，永远不要拿新模式替换旧列表（曾把 node-pty/serialport 塞回 asar 导致串口+终端全废）。
10. **`spawnSync` 在主进程会卡住渲染层 IPC**。任何「输入即查」的下拉（如板卡搜索），后面是 `spawnSync` 的一律要防抖。
11. **先写测试再修代码**。测试能区分「是代码错还是我错」——多轮经验里，失败的测试里有相当一部分是**测例自己写错**（编造工具不打印的输出形态、误读判定规则、把真代码当注释）。别一红就动手改代码。
12. **静态扫描器必须造样例反向自测**。四件套初版分别产出过 267 / 130 / 22 条**假阳性**。口径宁漏勿误报，命中后人工核实。

## 8. 🚧 死胡同（别重走）

- `file://` 下渲染层 module script **静默不执行**（探针恒 0 且零报错）→ 整树启动验不了，别反复试。
- CDP（`Runtime.evaluate`）在本机 Chrome 上**连 about:blank 都超时**，不稳定。
- 走本地 http 后 Monaco 9MB 在 headless 里跑不完。
- 沙箱里打包产物 **spawn 不动 arduino-cli**（Bash 直跑正常）→ 烧录端到端只能真机。
- `check-render-boot.mjs`（Chrome 探针）在沙箱超时、`check-ui-assets.mjs` 需传安装包目录参数——**这是环境/用法问题，不是回归**。
- **JS 正则不支持 `\A`**：`\ATP` 会被当字面量 `ATP` 匹配（`logExplainer` 曾因此误报）。
- **写二进制夹具别用 JS 字符串 `\xff`**：那是 U+00FF（UTF-8 占 2 字节），不是字节 0xff。用 `Buffer.from([0xff,...])`。分区表 label 真实是 `0x00` 收尾。
- **CMSIS-SVD 的 `derivedFrom` 是属性**（`<peripheral derivedFrom="GPIO">`），不是子元素。
- **ESP32-S3 / C3 / P4 原生 USB 共用 `303a:1001`**（硬件事实，物理分不开）→ 插 C3/P4 **不要**指望自动认准，得由用户/端口信息收窄。
- **`esp32-p4-function-ev` 是 PlatformIO-only + `svdChip:null`**（P4 无 arduino-cli 官方 core），属**合法收录**，别当成漏配去"修"。
