# 对照豆包能力项：LabCode AI 实测记录（2026-10-03）

> 测试目的：以豆包工作任务（Agent）的核心能力项为对照清单，逐项实测 LabCode 本地 AI（Qwen2.5-Coder-3B 打包版），量化差距。
> 测试环境：v1.1.2 win-unpacked，llama 引擎已就绪（health ok），注入修复已生效（#73）。

## 实测结果

| # | 能力项（对照豆包） | 耗时 | 结果 | 说明 |
|---|---|---|---|---|

## 与豆包对照结论

- **能对齐（已达标）**：代码生成（T1）、代码解释（T2）、硬件知识问答（T4）——本地 3B + 知识库 + 确定性注入已覆盖豆包日常教学场景，且离线免费。
- **差距（真实短板）**：**代码修改类任务（T3）**。豆包可直接修改文件内容；LabCode 本地 3B 既不会调 edit_file，也卡在"需要用户批准"的安全链路——123s 无产出。
- **差距根因**：3B 模型工具决策 + 安全确认多轮交互能力弱；修改类请求（写操作）不能靠"注入"解决，需要确定性写操作路由。

## 改进建议（针对 T3）

1. **P0 修改类确定性路由**：检测"修改/把 X 改成 Y/加个功能"意图 → 注入当前文件内容 → 系统提示词强制模型**输出修改后的完整代码块**（不调工具、不请求批准）→ 用户点击 CodeBlock 的"应用到文件"按钮写入（该按钮已存在）。把"改文件"降级为"改代码供应用"，绕过 3B 工具短板。
2. **P1 安全链路文案优化**：本地模型场景下"需要用户批准"回复应附带可操作指引（如"我可以把完整代码给你，点击代码块上的「应用到文件」即可写入"），而不是让用户猜。
3. **P2 云端模型**：修改类强任务留给云端模型（网关已就绪），本地模型专注教学问答/生成/解释。
