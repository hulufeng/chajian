## 四、测试用例

### P0 — 阻断级（任一失败即停止放量）

#### TC-01 安装与启动
1. 从 `https://bluebubai.work/updates/LabCode-Setup-1.2.35.exe` 下载安装包（约 371MB）。
2. 双击安装，可选择安装目录；完成后桌面/开始菜单出现 BubaiCode 快捷方式。
3. 启动软件，观察：标题栏正常、左侧活动栏有文件/插件/本地模型等图标、无白屏无闪退。
- **预期**：安装成功、启动到欢迎页、状态栏显示「后端就绪」、控制台无红色报错。

#### TC-02 登录
1. 点击右上角头像/登录入口，弹出登录框。
2. 输入内测账号邮箱 + 密码，点登录。
3. 观察登录框关闭、右上角显示账号邮箱。
- **预期**：登录成功（提示额度），错误密码有明确提示；登录态重启软件后仍保留。

#### TC-03 新建 / 打开 ESP32 项目
1. 新建 Arduino 项目，确认生成 `.ino` + `.bubaicode.json`。
2. 或打开已有 ESP32 项目，确认编辑器显示代码、文件树可见。
- **预期**：项目正常加载，Monaco 编辑器可编辑，不出现空白页。

#### TC-04 编译
1. 打开 ESP32 项目，点工具栏编译按钮（或 AI 面板说"编译"）。
2. 等待编译完成，查看输出区。
- **预期**：显示 `Sketch uses ... bytes (xx%)`、exit 0；失败时有明确错误日志而非无响应。

#### TC-05 插件安装
1. 打开插件面板 → 官方市场，确认能看到 9 个插件。
2. 选一个未安装插件安装（如 Wokwi 模拟器）。
3. 切到"已安装"标签确认。
- **预期**：下载进度正常、安装成功、已安装列表出现该插件；**不要出现 ETIMEDOUT / GitHub 连接超时**（下载走 `bluebubai.work` 中转）。

#### TC-06 烧录（有板卡的内测用户）
1. 接好 ESP32-S3 开发板，确认设备管理器里端口状态为 OK（不是 Unknown/phantom）。
2. 软件里选择端口，编译并上传。
3. 观察上传日志。
- **预期**：esptool 显示 `Chip type: ESP32-S3`、`Writing ... Hash of data verified`、`Hard resetting`；无 `This chip is ESP32-S3, not ESP32` 报错。

### P1 — 重要功能

#### TC-07 AI 写代码 / 改 bug
1. 在 ESP32 项目里故意写一处编译错误（如 `delayy(500)`）。
2. 编译，确认失败并拿到错误日志。
3. 使用「AI 修复编译错误」功能（或让 AI 改 bug）。
4. 查看修复后的代码，重新编译。
- **预期**：AI 给出修复后代码并写回（原文件备份 `.aifix.bak`），修复后可编译通过。

#### TC-08 本地模型（免登录）
1. 未登录状态下，切换模型为本地模型（如 Qwen2.5-Coder 3B/7B）。
2. 发一条消息。
- **预期**：本地引擎启动、有回复内容；不要求登录。

#### TC-09 云端模型（已登录）
1. 登录后，选择云端模型（DeepSeek / Qwen 等）。
2. 发一条消息。
- **预期**：正常回复、额度扣减可见；额度不足时有明确提示。

#### TC-10 串口监视器
1. 接板，打开串口监视器，选择正确端口和波特率（如 115200）。
2. 观察程序 `Serial.println` 输出。
- **预期**：能打开端口、有数据回显。
- **已知情况**：开发组实测中 ESP32-S3 原生 USB-Serial/JTAG 口（COM31）在烧录后读不到回显，判断为板卡复位时序特性而非软件 bug；内测如遇此情况请记录板型/端口/现象，不必视为阻断。

#### TC-11 自动更新
1. 打开软件，触发检查更新。
2. 确认识别到最新版本并给出下载/安装入口。
- **预期**：`latest.yml` 指向 1.2.35，能下载安装；不出现 404。

### P2 — 体验与兼容

- TC-12 浅色/深色主题切换后各面板显示正常。
- TC-13 AI 面板窄宽度下输入区不被挤压、过程信息可折叠。
- TC-14 多项目切换时标签页/文件树正确刷新。
- TC-15 卸载后无残留进程，可重新安装。

## 五、验收标准

| 级别 | 定义 | 放量条件 |
|---|---|---|
| P0 通过 | 安装/启动/登录/项目/编译/插件/烧录全部可用 | **必须 100% 通过**，任一失败暂停放量 |
| P1 通过 | AI 改 bug / 本地模型 / 云端模型 / 串口 / 更新可用 | 允许 ≤1 个非阻断问题，需有规避方案 |
| P2 通过 | 主题/排版/多项目/卸载 | 记录为优化项，不阻断放量 |

## 八、开发组回归命令（内部）

```bash
cd desktop-app
npm test                    # 14 脚本 / 115 断言，当前全绿
npm run build:win           # 构建安装包（输出 dist<next>）
```

构建注意（踩坑记录）：
- CodeBuddy 注入的 `NODE_OPTIONS` shim 会让 electron-builder 清空目录时 trash 失败 → 构建前 `set NODE_OPTIONS=`、`CODEBUDDY_SAFE_DELETE_ENABLED=0`。
- 构建前确认无 BubaiCode.exe 进程占用产物目录。
- `copying Electron` 阶段需耐心等 2~4 分钟，不要误判失败。
- 安装包写入完成判定：大小两次采样相等（约 389MB）。
- 国内分发：插件下载/自动更新必须走 `bluebubai.work`，**不要直连 GitHub**（实测 GitHub Releases IP 超时）。
