## 二、LabCode 最新实测（v2，2026-10-04，全部打包版实测）

### 2.1 四项能力（对照豆包工作任务能力项）
| # | 任务 | 耗时 | 结果 |
|---|---|---|---|
| T1 | 代码生成："写一个 ESP32 按键控制板载 LED 开关的 Arduino 程序（按键消抖）" | 6s | ✅ 完整程序：INPUT_PULLUP 消抖、pinMode、Serial.begin 均正确，代码块带「应用到文件」 |
| T2 | 代码解释："解释当前打开的文件做了什么" | 6s | ✅ P0 注入生效：自动读当前文件（01-blink.ino）真实内容并逐段解释 |
| T3 | 代码修改："把当前打开文件里 LED 闪烁的 delay 改成 500ms" | **3s** | ✅ 修改路由：直接输出修改后完整代码 `delay(500)` 两处已改，代码块带「应用到文件」按钮 |
| T4 | 硬件问答："ESP32 的 ADC 引脚使用注意事项" | 3s | ✅ 知识库命中：ADC1/C3、12 位 0-4095、超 3.3V 分压、3.3V 电平、40mA |

### 2.2 关键实现（v1→v2 差距修复记录）
- **P0 确定性文件注入（修复 T2"40s 反问"）**：检测"读取/查看/分析文件"意图 → 从主进程实时读当前文件内容注入上下文 → 模型基于真实内容回答。实测 40s 反问 → 6s 真实回答。
- **工作计时器（对齐 TrieCode"▶ 已工作 16s"）**：busy 时统计栏显示"▶ 已工作 Ns"高亮跳动。
- **修改类确定性路由（修复 T3"123s 批准死路"）**：修改意图 → 空工具集单轮对话（runModify）→ 模型直接输出修改后完整代码块 → 用户点「应用到文件」写入。实测 123s 失败 → **3s 通过**。
- **token 计量条**：输入/输出 token 实时显示（本地模型免费，等价替代 TrieCode 积分条）。

### 2.4 第二轮深度对比（2026-10-04，v2 追加）：多轮/组合/边界/未知问题

| # | 任务 | v1 实测 | v2 修复后 |
|---|---|---|---|
| T5 | 多轮追问（"ESP32 用什么语言编程" → "和 C 有什么区别"） | ❌ 第二问跑偏（答成"LabCode 是智能体"） | ✅ 3s：正确理解"它"=ESP32，答出硬件支持/库与工具的区别 |
| T6 | 组合任务（写 DHT22 程序 + 解释关键函数） | ❌ 误判 read_file（"读取"裸词）→ 幻觉路径 src/main.ino → 20 轮耗尽 | ✅ 6s：直接输出完整 DHT22 代码块（DHT.h/readTemperature）+ 可应用 |
| T7 | 边界问题（知识库未覆盖："ESP32 能不能播放 MP4"） | ❌ 反复试工具 20 轮耗尽 | ✅ 6s：直接答"不直接支持，可用 FFmpeg 解码/云服务" |

**v2 修复（关键架构调整）**：**本地模型默认走"无工具单轮对话"（runChat）**——仅 detectRequiredTools 命中明确操作词（编译/烧录/写文件/打开等）才进 Agent 工具循环；同时收紧 read_file 判定（去掉裸"读取"误判）。3B 模型不再有机会在未知/组合任务上死循环，全部任务 3-6s 文字/代码回答。
- 实测：T5/T6/T7 全部 6s 内完成；第一轮 T1-T4 回归全绿（6s/6s/3s/6s）。

## 六、结论（v2）

- **LabCode 本地 Agent 已完成"豆包/TrieCode 日常教学场景"四项能力覆盖**：生成/解释/修改/问答全部 3-6s 离线完成，且带「应用到文件」等确定性交互——定位"离线教学助手"基本盘成立。
- **差异化不变**：离线 + 真实烧录闭环 + 0 成本；TrieCode/豆包是"云端全能 Agent"。
- **商业化路径**：本地守基本盘 → 云端模型（网关）补高级 Agent 付费点 → 计时/token UI 建立信任感（已完成）。
- **本次产出**：T3 修改路由（v2 核心修复，123s→3s）；三方对比报告 v2。
