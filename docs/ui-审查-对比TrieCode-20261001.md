## 2. 发现问题清单

### P0-1 语音识别实际走在线引擎，报错刷屏（本次实测新发现）
- 现象：AI 面板连续出现 3 条「语音识别失败：network」
- 根因：**Chromium 的 Web Speech `SpeechRecognition` 桌面端引擎是 Google 在线服务**，非本地识别；无外网/被墙时必报 `network`。
- 影响：此前「Web Speech 本地识别」的交付结论需修正为「在线引擎，依赖网络」；报错无去重会刷屏。
- 处置：① 错误提示去重限流（同类型 30s 内仅提示一次）；② 文案如实说明「在线识别引擎不可用」；③ **后续方案：whisper.cpp 本地 STT**（与本地模型 llama.cpp 同架构，GGUF 下载链路/内存小可复用）——列入待办，用户确认后开发。

### P1-1 AI 面板 320px 偏窄
- 对话气泡、代码块、工具日志在 320px 内排布拥挤（对比 TrieCode 侧栏亦窄，但 TrieCode 有消息操作菜单横向空间占用更小）。
- 建议：面板宽度可拖拽（200-480px，复用 TrieCode 插件左侧栏响应式骨架：输入框 `flex:1 1 auto + min-width:0`、按钮 `flex-shrink:0`、行 `flex-wrap`）。

### P1-2 AI 消息区无操作能力
- TrieCode 每条消息有：重新生成 / 编辑重发 / 回退到这里；codelab 目前只有发送+滚动。
- 建议：先做「重新生成/编辑重发」两个高频操作（深度报告 §15 已有实现参考）。

## 4. 结论与建议（按优先级）

1. **本轮已修复**：语音错误刷屏（去重限流 + 如实文案）。
2. **短期（本周）**：AI 面板加宽度拖拽（200-480px）；消息区加「重新生成/编辑重发」；语音改 whisper.cpp 本地识别（复用本地模型下载链路）或临时移除按钮。
3. **中期（Agent 路线图）**：工作日志轻量版、上下文用量条、状态栏 AI 用量。
4. **已确认合理不动**：标题栏 40px、状态栏 24px、编辑器主区 813px、面板贴齐无遮挡。

## 4.1 对齐 TrieCode 补齐功能（2026-10-01 已开发完成并实测）

| 功能 | TrieCode 参考 | codelab 实现 | 实测结果 |
|---|---|---|---|
| 消息操作 | 重新生成（重发上一条提问）/ 编辑重发 / 回退到这里（rewindBarrier+redo） | `AiPanel.tsx`：重构 `doSend(text, historyOverride?)` 统一发送入口；`regenerate(i)`（截断+重发该条）/ `editResend(i)`（截断+文本回填输入框聚焦）/ `rewindTo(i)`（截断到该条）；user 消息 hover 显示三个操作按钮（`.ai-msg-ops`） | ✅ CDP 实测：发送真实消息后 user 气泡显示 3 按钮；回退点击后消息截断正确；编辑点击后输入框填充+消息截断 |
| 面板宽度拖拽 | 插件左侧栏 200-480px 响应式骨架 | `.ai-panel-resizer` 左缘 6px 拖拽手柄（mousedown+window mousemove/mouseup），200-480 clamp，localStorage `codelab-ai-width` 持久化 | ✅ 320→460 拖拽生效并持久化 |
| 上下文用量 | 上下文用量 N%（total/max+剩余）+ 手动压缩 | token 面板动态化：对话消息按"字符数/1.5"估算 token（`dialogTokens` useMemo，含引用上下文）、16K 窗口百分比、工具记录条数；压缩按钮文案"保留最近 10 条" | ✅ 面板显示"消息 1 条 · 估算 67 tokens · 16K 窗口 0%" |
| （未做，属 Agent 路线图） | 工作日志步骤卡片 / 审批弹窗 / 计划面板 / 文件冲突三方 / 上下文手动压缩（引擎级 doCompact） | — | 依赖 Agent 引擎权限/计划体系，待深度报告 §8 路线落地 |

**redo 说明**：TrieCode 有 rewindBarrier+redoRewind（回退可恢复）；codelab 当前为轻量"回退即截断"（无 redo），如需对齐可后续加快照栈（最多 20 条，chat store 同款）。
